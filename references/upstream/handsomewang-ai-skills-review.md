## 结论

可以借鉴通用方法，但不能把该项目当成完整跨境选品 Skill，也不应把源码直接合入本仓库。

上游实际是 1688 供给研究流程：自然语言需求转关键词、从已登录 Chrome 会话读取第一屏商品与店铺信息、合并去重、做价格/销量/属性/供应商分析，再生成 Excel 和 Markdown。

它没有卖家画像、SOP、决策日志、Amazon/SHEIN/TikTok/DTC/Reddit 需求数据、完整成本/合规层或测试体系。因此在本项目中只能对应“1688 供应链验证适配器”。

## 可借鉴的方法

- 宽窄关键词组合并让用户确认；
- 原始数据、确定性分析和 Agent 语义判断分层；
- 明确第一屏样本局限；
- 用稳定商品 ID 去重并隔离被拦截行；
- 同时看供应商主营品类和客观服务字段；
- 不把某供应商高销量包装成应照抄的跨境爆品。

这些方法已在本项目中独立表述和实现为数据契约与策略，没有复制上游代码、提示词或模板。

## 不能直接采用的部分

- 无画像就开始推荐；
- 把 1688 第一屏当市场全貌；
- 把供应商销量当目标平台消费需求；
- 把自定义供应商分数当作事实质量结论；
- 把人工过滑块的 CDP 爬虫当正式数据主链路；
- 使用共享临时目录或共享 Chrome profile，破坏多卖家隔离。

## 工程风险

- 上游综合商家分的权重没有校准来源，缺字段重新归一后可能高估样本；
- 样本三等分价格带不能证明自然价格分层；
- 价格解析未充分表达阶梯价、SKU、单位和 MOQ；
- 浏览器登录态自检与并发隔离有限；
- 没有离线 fixture、回归测试、数据质量阈值或多用户测试。
