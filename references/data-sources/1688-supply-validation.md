# 1688 供给侧验证适配器

知识类型：经验型流程与数据处理框架。1688 页面数字只有在保留来源、采集日期和样本边界时才是本次运行的可核验数据。

## 定位

1688 适配器回答“去哪找货、供给价格和 MOQ 如何、供应商是否专业、能否定制与稳定交付”。它不回答“Amazon/TikTok/SHEIN 用户是否会买”。

本流程受 HandsomeWang/AI_SKILLS 中 1688 供给洞察思路启发，但未复制其代码、SKILL 文本或报告模板。审计与许可证边界见 `references/upstream/handsomewang-ai-skills-review.md`。

## 输入

- `seller_id` 与已读取的 profile/SOP/最近 10 条决策；
- 目标平台、国家和目标产品描述；
- 用户指定关键词，或待确认的 3–5 个宽窄关键词；
- 只读 MCP、用户导出文件或用户授权的浏览器可见数据。

## 关键词策略

关键词组合应覆盖：

- 核心品类词；
- 常见同义词或上位词；
- 材质/规格；
- 使用人群或场景；
- 用户想验证的差异化方向。

“销量高”“优质”“便宜”等通常是分析意图，不必硬塞进每个搜索词。用户已明确关键词时，直接使用并记录，不重复询问。

## 最小字段

| 维度 | 最小字段 | 用途 |
|---|---|---|
| 商品 | 稳定商品 ID、标题、链接、类目、属性 | 去重与语义判断 |
| 报价 | 币种、阶梯价、对应数量、SKU/单位 | 避免只取第一个价格造成误判 |
| 采购 | MOQ、样品价/打样费、交期 | 资金与测款门槛 |
| 物流 | 重量、尺寸、材质、敏感属性 | 头程与合规核实 |
| 定制 | 包装、Logo、颜色、模具、最小定制量 | 差异化可行性 |
| 供应商 | 主营类目、经营年限、地区、服务字段 | 供应商专业度与稳定性假设 |
| 跨境 | 出口/跨境经验、可提供资料 | 能力匹配；缺失时不得默认有 |

## 客观层与语义层分离

确定性程序可以计算：样本数、缺失率、价格/MOQ 分布、属性频次、同一供应商命中数、可用服务字段。

Agent 再做语义判断：供应商主营与目标品类是否高度匹配、命中商品是主力还是边缘、是否具备卖家需要的定制能力。

报告必须把“客观字段”和“语义匹配判断”分栏。不得把自定义综合分描述为平台官方质量分。

## 样本边界

- 记录每个关键词实际采集的页数和条数；
- 只有第一屏时写“便利样本，不代表市场全貌”；
- 价格分位数只是当前样本切分，不得称为自然形成的主流价格带；
- 同一店铺多条商品不得在店铺标签统计中重复计数；
- 被拦截、字段空白和解析失败的行单独计数；
- 抓取时间、登录区域、个性化排序可能影响结果，应写入局限。

## 进入最终选品的方式

- 采购、MOQ、打样与物流字段影响 `margin`；
- 交期、定制、供应商专业度和跨境经验影响 `capability_fit`；
- 敏感材质、证书缺失、超资金与不支持物流进入过滤或待核实；
- 1688 单店销量不能直接增加目标平台 `demand`；
- 缺失重量、尺寸、MOQ、交期或关键资质时，候选进入 `blocked_pending_data`，不伪造精确利润。

## 浏览器采集边界

浏览器模式不是默认生产接入。只有用户明确授权、已登录且平台条款允许时才运行；遇到验证码或行为校验必须由用户处理，不绕过安全机制。

正式交付优先顺序：只读 MCP/API > 用户导出文件 > 浏览器辅助采集 > 合成演示。任何模式都必须按 `adapter-contract.md` 归一化并保留离线 fixture。
