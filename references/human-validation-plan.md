# 真人复盘与盲评 A/B 执行包

> 这两项实验不依赖 learned v2 内核，可与代码实现并行。真实卖家资料不得提交到公开仓库；只允许把脱敏后的聚合结论或虚构样例用于录屏。

## 实验 1：最近一次真实选品复盘

### 目的

验证卖家的关键判断是否真的散落在数据工具、表格和对话之间，以及 profile、SOP、决策日志能否无损保存“当时为什么做/不做”。本实验不验证推荐能提升利润。

### 参与者与时长

- 1–3 位近期做过选品决策的跨境卖家；
- 每人 45–60 分钟；
- 优先选择能展示一份真实来源报告或当时工作表的人。

### 输入

- `references/questions/recent-selection-retrospective.md`；
- 卖家当时使用的只读报告、表格或截图；
- 3–8 个当时考虑过的候选品；
- 后来结果可以记录，但必须与“当时可见信息”分开。

### 主持流程

1. 先确认 `seller_id`，在私有工作区执行 `intake-interview`；
2. 让卖家按时间顺序回放：看了什么、保留什么、否决什么、为什么；
3. 对每个候选确认候选 ID、当时决定、原话、标签、来源报告和决策日期；
4. 来源报告不存在时，将来源类型记为 `historical_retrospective`，使用显式 session ID；若没有显式 ID，退回当时事件日期；
5. 通过 `recommendation-review` 写入决策日志，不直接生成 active learned 规则；
6. 让卖家逐条核对 profile、SOP 和 decisions，记录遗漏、误分类和修改次数。

### 成功指标

| 指标 | 通过线 |
|---|---:|
| 卖家确认“关键理由被正确保存”的决策占比 | ≥ 80% |
| 需要主持人补写或改写的决策占比 | ≤ 30% |
| 能引用到明确来源报告或复盘 session 的决策占比 | ≥ 80% |
| 卖家认为下次选品会复用的字段/规则 | 至少 2 项 |

### 必记失败信号

- 卖家无法区分当时判断与后来解释；
- 拒绝理由只能落到“个人不喜欢”；
- 来源报告无法与候选 ID 对齐；
- 画像字段不足以表达关键约束；
- 卖家认为维护文件的成本高于复用价值。

## 实验 2：画像感知 vs 通用推荐盲评 A/B

### 目的

验证画像记忆是否提高推荐的相关性、解释可信度和可执行性。它不是利润因果实验，也不能用合成数据证明经营收益。

### 设计

- 使用同一批候选、同一事实数据和同一成本缺口；
- A 版不读取卖家 profile/SOP/decisions，只按平台通用策略输出；
- B 版读取卖家记忆并输出个性化过滤、排序与双向归因；
- 两版隐藏生成方式，随机交换 A/B 标号；
- 不向评审者透露哪版是“画像版”；
- 每位卖家独立评分后再揭盲，避免主持人引导。

### 评分表（每项 1–5 分）

| 维度 | 问题 |
|---|---|
| 相关性 | 候选是否符合你的资金、平台与供应链现实？ |
| 排雷能力 | 报告是否提前识别你真正会否决的品？ |
| 解释可信度 | “适合/不适合”的理由是否像你的判断，而不是套话？ |
| 可执行性 | 你是否知道下一步该核实什么、放弃什么？ |
| 决策信心 | 报告是否让你更有把握进入样品/核价阶段？ |

另外强制回答：

1. 你会选择哪一版继续使用？
2. 哪一条建议最像“知道你过去踩过的坑”？
3. 哪一条个性化理由是错的或多余的？
4. 如果两版都不够用，缺的首要数据是什么？

### 最小样本与判定

- 最小试跑：3 位卖家，每人至少 1 个真实候选批次；
- 候选信号：画像版在“相关性、排雷能力、解释可信度”三项中至少两项平均领先 0.8 分，且多数卖家盲选画像版；
- 反证信号：两版差异主要来自文案长度，或通用版同样能命中拒绝理由；这意味着记忆层尚未贡献独立价值。

## 数据与公开边界

- 真实 `sellers/{seller_id}/`、`reports/{seller_id}/` 必须在私有 Git 仓库或等价的受控私有工作区；
- 公开仓库的 `.gitignore` 会排除真实卖家目录，因此不能宣称公开配置自动提供 profile 变更历史；
- 录屏只展示 `_example` 虚构数据、空白模板或卖家书面同意后的完全脱敏截图；
- 对外只报告参与人数、评分分布、主要失败模式与下一步，不公开原始经营数据。
