# 最近一次真实选品复盘评测

这组 cases 验证 `intake-interview` 与 `recommendation-review` 能否把一次真人复盘变成可审计的决策记忆。它不验证选品是否赚钱，也不使用公开仓库中的真实卖家数据。

## 验收方式

1. 在临时或私有 seller 目录中执行访谈；
2. 按 `cases.json` 提供输入；
3. 检查复盘报告、逐候选 decision 文件和 profile diff；
4. 真实数字、账号、店铺、原始报表均不得提交公开仓库。

## 硬门禁

- “当时决定”与“后来结果”必须分开，不能用结果倒写当时决定；
- `recalled` 数字不得进入事实评分或变成硬阈值；
- 一条拒绝不得直接升级为 learned 规则；
- 三条不同候选证据最多生成 `confirmed: false` 候选，人工确认前不得影响排序；
- 每个候选一个 decision 文件，且只写入当前 seller_id；
- 未经用户确认，不修改 profile A/B/C 和 SOP 正式规则。

## Case 覆盖

| Case | 目的 |
|---|---|
| IR01 | 接受决策后来失败，两个状态仍被分别保存 |
| IR02 | 事后回忆的 CPC/认证费只能标 `recalled` 并进入待核实项 |
| IR03 | 三个独立拒绝可提议规则，但只能是未确认候选 |
| IR04 | 无 seller_id 或无画像时必须先建档，不直接写历史决策 |
